# tests/probes/ —— 真机探针（默认不编译）

Cargo 只自动发现 `tests/*.rs`，**不递归子目录**。本目录的探针只要不在
`Cargo.toml` 里显式登记 `[[test]]`，就完全不参与 `cargo build` / `cargo test`——
省的是编译时间（CurSeen 实测：登记 16 个测试二进制 1m55s vs 不登记 5 个 1m29s，
「差的 26 秒里一个断言都没跑」）。

## 什么时候放这里

- 需要**真 DLL 文件**（`.build/decoders`）或真实文件系统布局的端到端验证；
- 跑一次 >10 秒，或有副作用（写临时文件、占独占资源）；
- 失败信息对「用户机器上怎么回事」有诊断价值。

纯进程内、毫秒级的判据放 `tests/*.rs`（门禁）或 `src` 内联单测。

## 写法模板（头部四件套 + 结构）

```rust
//! 一句话定性：这个探针验证什么行为。
//! 背景/动机：为什么要单独一条（历史现场 / 用户报障 / 实测发现）。
//! 判据：锁哪几件事（不楔住 / 不越界 / 产物完整 …）。
//! 跑法：临时在 Cargo.toml 登记 [[test]] 后 `cargo test --test <名> -- --ignored`
#![cfg(windows)]

const SOME_THRESHOLD: u64 = 40_000_000; // 判据常量化，每个常量带量纲+理由

#[test]
#[ignore] // 慢探针必须 ignore；fast 探针可不 ignore 直接进门禁（分组与 ignore 是两个独立决定）
fn behavior_style_english_long_name() {
    // …
}
```

- 测试名 = 行为式英文长句；判据常量化并带理由注释。
- 探针有进程级副作用（环境变量等）时写清理函数——一个用例提前 panic 会污染同文件后续用例。
