## 八、探针与实测方法

### K197 —— 最小化位是系统给的，z 序才是程序给的：验"唤回窗口"别数 `IsIconic`

- **现象**（2026-11-05，m235）：给多开补"点托盘把开着的窗口一起唤回"。探针先开三扇窗、
  全部 `ShowWindow(SW_MINIMIZE)`、触发唤回、数 `IsIconic` —— 连**只唤回一扇**的旧版也报
  `restored=3/3`，与源码直接矛盾。若照这个判据收工，等于把"没改"记成"改好了"。
- **对照臂定案**：`-SkipWake 1`（最小化后什么都不做，等满 8.8 s）仍保持 3/3 最小化 ⇒
  恢复确实由唤回触发，不是探针自己漏了什么。再加一条**覆盖窗**臂才把差别量出来：用
  `System.Windows.Forms.Form` 造一个无关窗口盖住三扇窗，读 z 序 ⇒ 旧版 **1/3** 回到覆盖窗
  之上（另两扇等了 8.7 s 仍在下面），新版 **3/3**、0.84 s。
- **根因**：一个进程重新获得前台时，Windows 会把它的**整组最小化窗口一起还原**（本机实测
  ~3.8 s 完成）。所以"`IsIconic` 全 false"根本区分不了"唤回 N 扇"与"唤回 1 扇"——那个位
  由系统决定，不由代码决定。
- **判据写法**：z 序 index 必须在**同一次 `EnumWindows` 遍历**里给所有目标窗与参照窗一起算
  （脚本里的 `ZMap`）；跨次比较会被窗口增删挤歪——实测同一次运行里参照窗的 index 就从 38
  漂到 39，而"在它之上有几扇"没变。
- **覆盖窗的三个坑**（都踩过）：
  1. 脚本起的窗 `Activate()` **抢不到前台**，实测 index=328（排在三百多个顶层窗口之下），
     z 序判据直接失真 ⇒ 要用 `SetWindowPos(HWND_TOPMOST)` 再 `(HWND_NOTOPMOST)`：
     先真正压到最上，再解除置顶，这样后续 `SetForegroundWindow` 才可能合法地压过它。
  2. `EnumWindows` 顺序**含不可见窗口**，全仓 300+ 条。要 index 可比，就必须对同一遍遍历里
     的所有窗口统一计数，不能只数"可见的那些"。
  3. 最小化窗在 z 序里贴底，所以**别把最小化与覆盖叠在一条臂里**——两个扰动会互相掩盖。
- **附注（工具坑）**：PowerShell 变量名**不分大小写**。脚本参数写成 `-Exe`、正文里又有个
  本地 `$exe`（指向硬链接出来的那份），后者把参数顶掉，于是 `Copy-Item $Exe $exe` 变成
  "复制到自己到一个还不存在的路径"，报 `PathNotFound`。参数改叫 `-Bin` 才干净。
- **教训**：**验证"窗口回到前面"时，最小化位是系统给的，z 序才是程序给的。** 任何"看起来
  会动"的窗口状态都可能被系统顺手补齐，探针必须配一条"什么都不做"的对照臂，否则系统行为
  会被记到程序头上；而且对照臂要能区分"没改"与"改好了"——本例里 `IsIconic` 区分不了，
  z 序可以。

### K198 —— 首帧暗、升级后变亮：两条显影腿各自算了一遍"自动曝光"

- **现象**（2026-11-08 用户实报）：打开 `noise.cr2` **已经出图**，停一会儿整张图**变亮**。
  不像卡顿、不像重画——是同一张图前后两帧的亮度不一样。
- **量具先行**：新写 `解码器仓 examples/probe_tier_brightness`，
  同一进程里跑两条腿并打均值。修复前：全尺寸 `mean=108.51` / 分箱 `mean=92.80`，
  **差 15.7 个灰阶**；再用十份真机样本跑批，**5 张有此现象**且方向不一
  （Panasonic GH4 −32.10、Sony ILCE-6300 +24.73、Canon G12 +9.64、Ricoh GR3 +2.28、
  Sony 7M2 +3.06），另 5 张差值 ≈0（所以当初只在噪点图上暴露）。
- **根因**：首帧走分箱档（`develop_binned`，p×p 面积平均），升级走全尺寸（`develop`）。
  两条腿**各自对"自己那份线性图"**调 `auto_gain`（99.9 / 99 分位 + 高光余量分档）。
  分箱把**噪点平均掉**了 ⇒ 99.9 分位掉到 `0.995` 阈值以下 ⇒ 判成"已经够亮"给 `1.0`；
  全尺寸腿噪点还在 ⇒ 给 `1.3929`。同一张图两个曝光，升级落屏那一刻就跳亮度。
  代码里那句 "They must share the same display exposure" 写了很多年，
  但**没有任何机制在 share**。
- **修法**：新增 `develop::scene_gain(img)` —— 统计源换成**未分箱的传感器原始样本**
  （按 `cfa_period` 切块、块内取归一化后的 max，Bayer 2×2 恰好等于 max(R,G,B)），
  **不做块内平均**。两条腿都调它 ⇒ 与尺寸无关、与是否分箱无关，天然同值。
  分位判据抽成纯函数 `gain_from_hist(hist, n)`，只有一处。
- **判据**：`probe_tier_brightness` 的 `delta`（两腿均值差）。修复后 10 份真机 + `noise.cr2`
  全部 **|delta| ≤ 0.24 灰阶**。绝对亮度回归：新旧全尺寸均值差最大 2.47 灰阶（2.3%），
  多数样本 0～1.3 ⇒ 观感不变。
- ★ 教训：**"共享某个量"写在注释里不算共享**，必须有机制（同源统计 / 同一份缓存）。
  凡是"同一份数据两条路径各自算一遍"的地方，都要问一句"两边算出来的会不会不同"。

### K199 —— 区域判据把「相对宽」当「绝对上界」：悬停判不在、命中判在

- **现象**（2026-11-08 用户实报）：缩略图条贴左 + 极简模式下，鼠标移到**关闭按钮**上，
  标题栏**不浮现**；但在这个看不见的位置单击，**照样把窗口关了**。
- **根因**：`Chrome::in_title_strip` 的 x 判据写的是 `abs_x >= 0.0 && abs_x < vw`——
  `abs_x` 是**窗口绝对坐标**，`vw` 是**视口宽（相对量）**。底条时 `vx = 0`、二者恰好相等，
  所以看着一直是对的；贴左后 `vx = 112`、`vw` 少一条宽，于是**最右侧那一条**
  （五颗标题钮全在里面）被判成"不在标题栏"。
  而 `hit` 的按钮矩形是**绝对坐标**（`vx + vw - …`），点击照常命中 ⇒ 悬停与点击两套结论。
- **修法**：`abs_x >= vx && abs_x < vx + vw`（两端都按视口原点算）。
- **判据**（不依赖任何具体数字）：`every_title_button_lies_inside_the_title_strip_for_both_viewports`
  ——遍历 `TitleBtn::ALL`，每颗钮的中心点在**底条与贴左两种视口**下都必须落在标题栏里；
  负向验证时它会准确报出 `Close 的中心 (880.0, 20.0) 不在标题栏里（view=(112.0, 0.0, 788.0, 600.0)）`。
- ★ 与 **K48** 同族：那条讲"绘制坐标减了原点"，这条讲"区域判据拿相对宽当绝对上界"。
  共性是**同一个 `vx = 0` 让两类错都看不出来**。凡是新增"视口原点非 0"的布局，
  必须把 `in_title_strip` / `activity` / `hit` / `paint` 四处一起核对坐标系。
