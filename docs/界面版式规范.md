# 界面版式规范

> **正本**。改版式先改这里，再改代码；代码与本文不一致时，以本文为准并当场修代码。
> 落地实现：`src/ui/tokens.rs`（数值）与 `src/ui/dialog_footer.rs`（结构）。
> 门禁：hygiene 第 14 查 `footer_buttons`——底栏按钮绕过共享函数就红。

## 一、为什么要有这份文件

2026-11-06 用户点名：「所有窗口的按钮要统一，底部间隔、左右间隔、与上一行间隔全都要统一；
通道调色的快捷键窗按钮和其它插件的就已经不一样了……让相同元素有一个共享的底层函数，
才能真正确保完全统一。」

当时三扇对话框各写各的：

| 窗口 | 四边留白 | 行间距 | 按钮行 |
|---|---|---|---|
| 插件设置 / 调色参数窗 | `padding(16)` + 行内再缩 16 | `spacing(0)` | 行内再加 `padding_xy(16,0)` |
| 裸数据参数窗 | `padding(16)` | `spacing(10)` | 紧接内容，不贴底 |
| 恢复提示窗 | `padding(16)` | `spacing(10)` | 靠一颗 `flex_spacer` 自己顶 |

三种数、三种归属。**收成一个函数**，横向与纵向才不会再次走散。

## 二、对话框（自绘窗口）版式 —— 写死

### 2.1 四个数，只有一个来源

| 量 | 值 | 令牌 | 说明 |
|---|---|---|---|
| 四边留白（左/右/上/下） | **16** | `DIALOG_PAD` | 内容列与底栏共用同一条线 |
| 行间距、按钮间距 | **8** | `GAP` | 内容行之间、相邻按钮之间 |
| 行高 | **40** | `ROW_H` | 内容行与按钮行同高 |
| 控件高 / 控件列宽 | 30 / 200 | `CONTROL_H` / `CONTROL_GROUP_W` | 输入类控件同宽右缘对齐 |
| 两列版式窗宽 | 480 | `DIALOG_W` | 由 `DIALOG_PAD`+`COL1_W`+`CONTROL_GROUP_W`+余量算出，**不写死**；插件设置窗与跳转窗共用 |

### 2.2 结构

```
┌──────────────────────────────────────┐
│ 16                                   │
│   内容行（高 40）                    │
│   ↕ 8                                │
│   内容行（高 40）                    │
│   ↕ 8                                │
│                    [弹性空白]        │  ← 内容短时把按钮顶到底
│   ↕ 8                                │
│                  [甲] [乙] [丙]  16  │  ← 按钮右对齐、间距 8
│ 16                                   │
└──────────────────────────────────────┘
```

- 一扇对话框**只有** [`dialog_footer::shell`]（或 `shell_split`）一个入口：它给出容器、
  四边留白、行间距、弹性空白与按钮行。各窗只负责往 `content` 里塞内容行。
- 按钮**一律右对齐**并**贴底**。贴底靠弹性空白，不靠算窗口高度——`fit_content` 有下限
  （`DIALOG_FIT_MIN`），内容比下限矮时窗口不会跟着缩，少了这颗按钮就会悬在半空。
- 底栏左缘与内容列左缘同一条竖线（都在「窗口左缘 + 16」）。**内容行不许再自己加左右内缩**：
  设置页的行是「页 16 + 行 16 = 32」，对话框用 `option_row_inset(..., 0)`，否则底栏与内容错开 16。
  ★ 带输入框的对话框也走这一条：不要用框架自带的 `Element::field`（它的标签列是 110、
  间距 12，都不是本表的数），用 `option_row_inset(标签, 输入控件.width(CONTROL_GROUP_W), 0)`，
  窗宽取 `DIALOG_W`。跳转窗 m277 之前正是踩在这一条上。

### 2.3 按钮文案与顺序

| 位置 | 次序 | 文案 |
|---|---|---|
| 右侧（主操作最右） | 对象级动作 → 确认 → 取消 | `另存为…` / `还原` / `确定` / `应用` / `取消` |
| 左侧（少见：纯对象级、与确认无关的） | 由窗自定 | 用 `shell_split` 的左组 |

- 参数窗（`Footer::Live`）**没有确定/取消**：关窗即结束，参数已经生效。
- 「另存为…」带省略号（会弹系统对话框）；「还原」不带（就地生效，不弹窗）。
- 文案不写截图/涂鸦一类过程名词，写动作本身。

## 三、设置页与其它非对话框版式

- 设置页沿用既有节奏：页 16、卡间 8、卡头↔正文 8、行高 40；`rows::option_row` 的
  行内 16 是**给设置页**的，不是给对话框的。
- 主窗口的画布、浮条、右键菜单不属于"对话框版式"，各自有裁定（见 `docs/产品定位与边界.md`）。

## 四、实施纪律

1. 新开一扇自绘对话框：`Window::new(..., DIALOG_W, ...).fit_content(DIALOG_FIT_MIN, MAX)` +
   `dialog_footer::shell(内容行, 右组按钮)`。不许出现 `Element::col().padding(...)` 自己搭壳，
   内容行也不许用 `Element::field` 或自定控件宽度。
2. 新加一颗底栏按钮：`dialog_footer::action(文案, 回调)`。不许 `Element::button(...)`。
3. 改间距/留白：只改 `tokens.rs`，然后跑 `2_scan`——`dialog_footer` 的几何判据会在
   340/480/640 三种窗宽下重算右缘、底缘与间距。
4. 本文与代码不一致时**当场二选一**：要么改代码，要么改本文，不许两边都放着。
