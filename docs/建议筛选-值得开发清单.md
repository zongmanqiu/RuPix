# 建议筛选：值得开发清单

> 来源：`.ex/其它/建议/1.txt` ~ `5.txt`（5 份网友建议，合计约 490+ 项）
> 性质：**候选清单**，不是裁决书、不是排期承诺。任一条目开工前仍要走既有裁决流程。
> 对读：[`产品定位与边界.md`](产品定位与边界.md) §5（明确不做 / 永久不提供）、[`待办.md`](待办.md)（唯一清单，卷首是收录判据）。

## 0. 一句话结论

5 份建议里的绝大多数，要么 RuPix 已经提供、要么已被宪章 / 裁决正面挡掉；
真正缺的、值得动的只有 **9 件事**，按优先级分三档。第 1 档是用户亲笔，第 2 档是看图
本业里没裁决的真实缺口，第 3 档是值得做但要先掂量形态的。

## 1. 筛选口径（三条过滤规则）

按此顺序收敛，全部命中即入清单：

1. **已实现 → 删。** exe 里现成能跑的，建议里列再多也不进清单：
   EXIF 深读面板（2026-10-25 补缺收敛）、直方图（levels 插件）、缩略图条、
   RAW / HEIC / AVIF / JXL / PDF / PSD 解码（8 档解码器）、主题深 / 浅、
   快捷键全自定义、WASD 平移、取色器、幻灯片、单进程多窗口、文件关联（HKCU）、
   右键菜单 / 底栏、CLI 探针（`--probe-decode` / `--bench-thumb` / `--safe-mode`）。

2. **已裁决 → 删。** 宪章 §5 写明「永久不提供」的，视为终局，
   **不再论证**：编辑（涂鸦 / 调色 / 裁剪 / 批处理）、管理（改名 / 删除 / 移动 / 收藏 / 标签）、
   导出与格式转换线、截屏 / 桌面贴图 / 壁纸、媒体库 / 人脸 / 相册 / 播放列表、
   云与账号、编解码库进 exe、WIC、自动更新与遥测、数据集与数据隔离之外的存储体系、
   多语言 / 强调色 / UI 缩放、GPU 加速、插件常驻与开机自启。
   裁剪只松了一半（编辑套件 = 用户「以后再做」），不得当作开工项。

3. **没实施、也没被裁决 → 留下。** 进入下面三档。

## 2. 三档清单

### 第 1 档：用户亲笔，必须做

1. **MCP / AI 接入面。**
   现状：CLI 只有 `--probe-decode` / `--bench-thumb` / `--safe-mode` 三个探针，
   AI 拿不到窗口态、批量分析接不进来、也无法编程式驱动。
   路径：先把 CLI 面扩成**稳定契约**（输出机器可读的 JSON，路径要支持含空格 / 中文），
   再评估是否常驻一个 MCP 服务（走进程外，和插件同一条路，宿主不引运行时依赖）。
   判据：MCP 层只是**入口与观察面**，不写回渲染、不持有解码后位图、不做 UI 操作注入；
   否则会活成第二套宿主。

2. **对外协议 `rupix://open?path=`（建议 1.txt #125）。**
   其它程序（VSCode 侧边栏、SumatraPDF 式调用方、脚本）一键调起看图器。
   顺带把「单实例窗口 + 传入路径即打开」这条既有链路压实：已开则把新图送进去，
   未开则开新窗口。验收看命令行是不是真的能当入口。

3. **面向其它软件的接入面。**
   与 2 同源。把「能被当作一个组件调用」的契约收进文档：
   命令行参数、协议 URL、窗口消息。常驻的协议入口收窄到管道 / IPC，不当功能套件做。

### 第 2 档：看图本业、未裁决的真实缺口

4. **放大镜（magnifier）。** 1.txt / 2.txt / 3.txt 都在点名。轻量看图器的正规交互件，
   与「看清」直接相关，没触及任何裁决线。实现面小（跟随鼠标的取景框 + 缩放渲染）。

5. **双图对比（A/B 并排或无边框贴边）。** 2.txt #58、4.txt 的 P1 都提。
   用途实在（修图、挑图、看细节）。注意：与「单进程多窗」是两码事，这是**一窗内两图**，
   不做窗口管理。

6. **剪贴板粘贴打开。** 4.txt 标的 ★ 必备。缺。实现面小（读剪贴板图片句柄 → 走既有解码入口），
   「复制 PNG 到剪贴板」这条已有的输出线正好配对。

7. **OCR 文本识别。** 不占宿主体积，另出**进程外插件**（仿 checkup / scan 路线），
   manifest 动态声明，宿主只有管道 / 共享内存两条既有通道，零新依赖。
   读出的文本走插件自己的文本窗，不写画面。

### 第 3 档：值得做，但先掂量形态再排期

8. **打印。** 2.txt 列为 P1，但看图器的打印形态（整页 / 缩放 / 多页 / 无边距）
   没有现成决策，且无插件承接。**先立样**（最简版：当前图送系统打印对话框），
   再决定要不要铺多页与排版选项。

9. **用户手册。** 用户亲提。它是文档工作、不是功能，与 1–8 不冲突，排期弹性最大。
   内容源：`README.md` + 快捷键表 + 插件体系说明。

## 5. 备注

- 本清单与 `待办.md` 的关系：`待办.md` 是唯一待办清单（2026-11-09 m291 合并后开项为 0），
  本清单不推翻它，只在「外部建议里有、我们没裁决」的缺口上补充候选。
  要开工时先按 `待办.md` 卷首的收录判据立条，再动代码。
- 归档顺序建议：先做第 2 档小件（4、5、6、7 全在 1 个版本内能落地），
  再做第 1 档的协议面，最后掂量打印形态。
- 筛选过程中没有任何一条建议被「吸收为需求」；吸收的只是信息价值。
