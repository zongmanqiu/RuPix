## 三、已知边界（不是待办，别当没看见）

| 边界 | 现状 | 什么时候动 |
|---|---|---|
| EXIF 落在文件前 12 MiB 之外 | 属性窗拍摄信息仍为空；**没有已知实例**：本机语料最深一枚在 19 KB，两枚 HEIC 在 2.5 MB 而该容器不解 | 出现真样本 |
| 衣角盲区的修复只有几何数值与负向验证 | 没有真机截图 | 把大图往上拖到极限，衣角应落在标题栏**下面**而不是消失 |
| 压缩包要"一层一层点"进去 | m296 起严格**一次只显示一层**：打开包只显示它根下的图，别的层要主动进。m300 起入口改成画面最外侧的**文件树**（右键「本包 ▸」整个撤掉）；树一次列全包里所有层。★ m302 起**首次建树那一趟就把各层的图全部落盘**（`L<层哈希>/` + `.rupix-ready`），「只落当前层」已不成立；变的只是**显示**仍一层一层 | 空层提示 m312 起按「有没有子层」分两句（有子层才指路到文件树）。层数很多时树要滚（m307 已有滚动指示）。★ **2026-11-10 用户裁定：不做层级前进/后退快捷键**——没必要为低频便利加动作与键位，位置感改用「树里标出当前层」（m309）；仍不引第二窗口 |
| 压缩包认四族，不认 iso / cab | m297 起认 `.zip` / `.cbz`、`.7z`、`.rar` / `.cbr`、`.tar` 与 `.tar.gz|.tgz|.xz|.bz2|.zst`；裸 `.gz|.xz|.bz2|.zst` 不算包（那是压一个文件）。**iso / cab 不做**：`iso9660` 0.1 自己标着 "Incomplete"，`cab` 是安装包、几乎不含图片集合，给不了承诺 | 真有人拿 iso 漫画镜像来问，再单独立项评估 |
| 固实包**首次打开**仍要解一遍 | m302 起首次建树那一趟把每一层的图都落到各自层目录并写就绪标记，之后切层只读层索引：`hand.7z` 实测各层 95–129 ms（改前 1928–2196 ms）。代价是首次多写一遍整包内容、磁盘峰值≈整包解压量；预落盘的整会话预算用完后，没落到的层退回按需展开（那时仍会等） | 超大固实包或磁盘占用成为问题时，再做「只解到目标条为止」的提前收尾 |
| 树的层级预算会截断 | m306 修好两处：① `build_tree` 的 `packs_left` 用完后旧写法**不置** `#truncated`（`else if` 只查字节与单包大小），第 65 个子包在树里显示成"0 张图、没有子层"、`--list` 也回 `truncated:false`；现按 `want_tree && packs_left == 0` 置位。② `tree_truncated` 与树节点同一批缓存（`canvas.rs` 的 reload），树底部显示一句「还有层没列出」，`capacity`/`hit`/`paint` 共用 `notice` 位让出一整行。预算没放宽，没展开的层仍没展开 | 已有；「重扫」要清 `tree.tsv` / `.rupix-tree`，撞「清理只有一处」纪律，**不做** |
| 建树会**预解**子包 | 为了让树一次列全，每个子包都要解出来读它的条目表（zip 的中央目录在文件末尾，没法只读一小段），中间包落 `_tree/`。★ m302 后**进层时不再产生第二份** `_nest/`：那一层的图已在预落盘里，`expand` 开头命中 `.rupix-ready` 直接返回；只有预落盘预算耗尽、退回按需展开的层才仍会走 `_nest/` | 若真机上磁盘占用成为问题，让建树直接复用 `_tree/` 里已落盘的那一份，别再写一份中间包 |
| 树的滚动没有视觉指示 | m307 已补：纵向滚动指示贴在树面板**右缘内侧**（视觉 6dp / 热区 16dp / 最小滑块 24dp，与缩略图条同一组尺寸），可拖滑块、可点轨道跳转；轨道只覆盖节点区，不压底部「还有层没列出」那一行；一屏放得下时既没有条也没有热区 | 已有。★ **树不加水平滚动条**：树宽是布局常量（`width_for` 26% 夹 112..184），横向滚动与「缩进表示层级」打架；名字被 `clip` 截断的解法是放宽树或悬停看全名，另议 |
| 加密 / 不支持的条目 | m304 修好两处：① `walk_zip` 的 `by_index` 会因不支持的压缩方法（LZMA / PPMd / ZSTD / 部分加密）直接报错，旧写法 `?` 上抛 ⇒ **整包打不开**（实测 3 张图里 1 枚 LZMA 就是 RC 3、0 层落地）；现在按 `ZipError` 类型跳过这一项并计入 `skipped`。② `Layer::skipped` 接到状态格，非 0 时追加「另有 N 项不支持」，数量与百分比不被替换 | 已有；RAR / 7z 侧的加密是否同样会整包挂，未实测 |
| 无头命令面读包只到根层 | m305 起 `--list` 直接认包：经 `core::archive::resolve` 展开**根层**并回 `archive` / `skipped` / `truncated`，`entries[].path` 是落盘真实路径，可接着喂 `--render`；目录输入响应逐字节不变。像素动词仍只吃真实路径，**没有包内定位语法**，子层只能走 GUI 文件树 | 适配器真要遍历子层时，再评估「包内定位」这套第二坐标系（会动契约与退出码语义） |
| 包内只有子目录的那一层是"空画面" | 画面空、给一句「这一层没有图片」；不当成打开失败（否则清单被清、左边的树也没了）。树里这种层用次要色画、图数不标 | 若真机上高频遇到，再考虑"自动下钻到第一个有图的子层" |
| 系统菜单跟着系统走，宿主不保证它长什么样 | 右键「系统菜单」是**转发** explorer 的文件菜单（m313）：装了 7-Zip 就有压缩、装了杀软就有扫描、改了默认看图器之后"打开方式"也在这里；没装就没有。宿主自己的菜单里**不会**出现这些动词（不复刻，否则内容就成了"我这台机器上长这样"）。原生菜单的明暗跟**系统**主题走，不跟本程序的「主题色」 | 若某类动词高频到需要固定入口（例如把「打开方式 ▸」单列），再在宿主菜单里加一项明确入口 |
