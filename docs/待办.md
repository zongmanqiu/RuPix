### 1. CORE-03 双页阅读

**目标**：把“页”变成阅读单元；LTR 最小集先落地，RTL/封面单页/横长单页/末页余数后置。

**数据模型**：

- 新增 `PageKey { path, page: Option<u32> }`：`page = None` 表示普通图片文件，`Some(n)` 表示页式文件的第 n 页。
- 新增 `SpreadUnit { left: PageKey, right: Option<PageKey> }`：一个阅读单元，`right = None` 用于封面/横长/末页余数。
- 阅读顺序与屏幕顺序分开：`ReadingOrder::Ltr / Rtl` 只决定 `left/right` 的取页方向，不改变页号本身。
- 主 Viewer 仍负责左页的解码与状态；右侧复用现有两栏绘制几何和异步解码，但不复用辅图的来源/固定/自由/活动窗状态机。
- 双页模式只保留一个页单元游标；状态栏、跳页、翻页都以单元为单位，例如 `3–4/164`。

**施工点**：

- `core/reading/`：`PageKey`、`SpreadUnit`、配对规则、单元步进、单元到主 Viewer 页号的映射。
- `core/viewer/`：把“当前页”抽象成可被单元驱动的入口；保持单页模式路径不变。
- `ui/canvas`：双页模式开关、双页布局（左/右 pane 或单页居中）、共享缩放/平移、状态栏与跳页换算。
- 翻页/跳页/胶片条：按单元换算；单页模式逐字节保持现状。

**第一版边界**：只做 LTR、页式文件和图片序列、共享缩放/平移；不做 RTL、封面单页、横长页、末页余数、per-book。

**验收**：单页模式回归全绿；双页模式能按 `1–2 → 3–4` 步进，状态栏、跳页、缩放、平移一致；关闭双页后恢复原来的单页状态。

### 2. CORE-04 连续阅读

**目标**：把多个页单元铺成可连续滚动的页框层；先纵向，横向后置。

**数据模型**：

- `PageFrame { key: PageKey, size, offset }`：页框层按阅读顺序排列，尺寸来自解码元信息。
- 视口状态：`scroll_y`（纵向）或 `scroll_x`（横向）、当前页、可见页范围。
- 预取窗口：视口前后各 N 页，复用现有解码队列；离屏页按距离淘汰。

**施工点**：

- `core/reading/` 的 `continuous` 子模块：页框布局、视口命中、当前页计算、滚动位置。
- `ui/canvas`：连续模式的绘制与滚轮/拖动分工；缩放只作用于整条页框层；状态栏/跳页按页框位置。
- 预取：按可见范围发请求，离开范围取消/淘汰；不与主图当前页抢队列。

**顺序**：最后做。它复用 CORE-03 的 `PageKey`/阅读顺序和 CORE-05 的 `scroll_pos` 字段；先纵向 MVP，横向不单独做一套。

**验收**：长条/多图连续滚动不闪白；滚轮滚动与缩放不打架；重开恢复滚动位置；单页/双页模式不受影响。

### 3. CORE-06 大目录首屏两阶段

**目标**：打开大目录里的图片时，先解当前图；目录枚举/排序在后台完成，清单就绪后再对齐当前项。

**施工点**：

- 打开文件时先造一个**单项临时清单**（只含当前路径），立即走既有解码；
- 后台线程跑完整清单，带回 `(世代, 目录, 排序, 结果)`；
- `Viewer::tick` 收结果：世代过期丢弃；路径仍是当前项才安装；保持已上屏的图，不重解；对齐当前文件后补预取；
- 排序变化 / 再次打开同目录另一张 / 清单构建失败都要让旧世代失效；
- 清单未就绪时，胶片条只有当前一格，状态可提示“目录载入中…”。

**边界**：第一版只覆盖“从文件打开”的普通目录；目录打开、流式清单、压缩包解包不做。

**验收**：大目录首图先出；清单到达后当前项不跳、不闪回；快速连续打开不同目录不串台；小目录行为与现在一致。

### 4. 大文件/大图解码首屏两阶段

**目标**：几百 MB 文件或超大像素图先出可看的预览，完整清晰度后到；不因大文件首屏长时间空白。

**施工点**：

- 先查元信息拿到自然尺寸，按“解码后像素量 + 文件大小”分档；
- 首请求只要**视口量级**的预览：解码器支持 `REQ_ALLOW_SCALED` 时走原生降采样；支持区域渲染的格式按可视区域重画；两者都不支持的格式仍走整解 + `fit_to`，但要在日志/状态里说清楚“正在整解”；
- 预览上屏后，在空闲时再补更高一档；补档不能顶掉用户已经发起的当前请求；
- 保留现有像素预算闸；不为了“能开”擅自放宽到可能 OOM 的尺寸；超限时给明确提示；
- 大文件只读一次、探针结果缓存，避免重复 IO。

**边界**：第一版不做瓦片金字塔 / 磁盘缓存；先做宿主侧“预览先出、整图后补”。

**验收**：大文件首屏先出预览；补档后清晰度提升且不闪白；普通图片首屏与当前逐字节一致；超限文件仍稳定拒绝。

### 5. CORE-07 压缩包首屏两阶段

**目标**：打开压缩包时先让当前页/当前层可用，剩余图片后台补齐；不因整包预落盘阻塞首屏。

**现状约束**：首次建树那一趟会把各层图片都预落盘，且 `.rupix-ready` 是“完整层”的唯一证据；改动必须继续保证这个标记不被半截层写脏。

**分两步**：

- **07a 止血**：首开只落当前层；其他层的预落盘改成可延迟/有预算的资产，首屏稳定后再做；不承诺“当前页先于当前层”。
- **07b 懒加载**：仅对可随机取条目的 ZIP/CBZ，先读中央目录建占位页；当前页 + 前后预取窗口按需物化，其余后台补齐。7z/RAR 固实包不做“只解当前页”的承诺。

**施工点**：

- `core/archive`：把“建树/条目枚举”和“图片物化”拆开；半物化层不写就绪标记；
- `core/viewer`：允许“路径尚未落盘”的占位页；导航时先物化再解码；过期物化结果丢弃；
- `ui`：首屏状态、失败/半物化提示；清单与胶片条按占位页显示。

**边界**：第一版不做全格式懒加载、不做瓦片金字塔；小包行为与现在一致。

**验收**：大包首图更早出现；连续翻页不积压；半物化不会误标就绪；切层/重开仍正确。

### 6. CORE-09 + CORE-08 压缩包合集连读（09 先、08 后置）

**目标**：把“一章一个包”的合集读成一本书。分两级落地：第一级只做显式的跨包导航（CORE-09），第二级才把子目录、子包拼成一条阅读序列（CORE-08）。

#### 第一级：CORE-09 相邻归档导航

**目标**：在当前归档翻到边界时，能显式跳到同目录的上一个/下一个归档；打开超大归档前先拦一道。

**施工点**：

- 从归档层目录反查原始包路径（`archive::here` 已有这个身份信息），扫父目录筛同族归档后缀，按当前排序口径做自然排序，得到当前包的下标；
- 菜单加「上一个归档」「下一个归档」两个**显式动作**，不改现有“末页循环回本包第一张”的语义；以后若确实需要“末页自动进下一包”，再加默认关的开关；
- 大归档闸：打开兄弟包前先读文件大小，超过阈值直接提示并跳过，不进入解包；条目数如果在格式层能便宜拿到再查，拿不到就只做文件大小闸；提示必须说清“哪个包、为什么跳过”；
- 走现有打开链路，归档会话目录、当前层、文件树、缩略图条随现有流程刷新；失败就停在原包，不把当前图弄丢。

**边界**：第一版只在归档**根层**启用；处在子层时置灰，避免“下一个归档”到底跳本包兄弟还是先回根层的语义歧义。

**验收**：根层可前后跳到兄弟包；排序与资源管理器/文件树一致；超限包被明确拒绝且原图不丢；子层里两个动作不可用。

#### 第二级：CORE-08 递归扁平化（后置）

**目标**：把一个合集里子目录、子包中的图片，按父链和排序拼成一条阅读序列。

**为什么后置**：

- 它依赖一个能把混合目录、跨层路径装进同一清单的页键/清单模型；当前清单默认单目录；
- 章节边界与双页配对冲突，需要与 CORE-03 一起定；
- 与 CORE-07 的顺序耦合：先做 08 会利用当前“预落盘”的便利，07 一改成懒加载就要返工；
- 第一级的显式跨包导航已经覆盖“合集连续读”的大多数场景。

**施工前置**：CORE-07 的懒加载页模型 + CORE-03 的章节边界 + CORE-05 的 book key。

**边界**：只做显式“并入子层”模式，不做默认扁平化；页数上限与截断提示必须一起做；跨章节不自动配双页。

**验收**：合集可按一条序列翻页；章节边界可辨；超限截断有提示；关闭模式后文件树与原有逐层浏览不变。

### 7. CORE-22 稳定帧 + 预约下一帧

**目标**：交互型视图变化（滚轮/按钮缩放、拖窗口、平移）停止后再出最终质量帧；手势中途不反复重解/换档，避免画面中途跳变。

**先测（开工闸）**：连续滚轮缩放 3–5 秒、连续拖动窗口边缘 3–5 秒，记录手势中解码/派生次数、是否有可见清晰度跳变、解码线程是否被中途请求占住。没有可复现抖动就保持现状，不实现。

**施工点**：

- `core/viewer`：把交互型视图变化的防抖从“首次交互后 120 ms”改成“最后一次交互后 80–120 ms”的尾随防抖；只作用于缩放/拖窗/平移，不作用于动画帧、翻页首屏、预读。
- 稳定帧落地后，再按现有 `tick` 补一次原图档/1:1；手势中途允许继续画旧档，但不发最终档请求。
- 保持现有 latest-wins 派生与在途取消；稳定帧请求不能被后续过期请求顶掉。
- 单测覆盖：连续缩放不中途发最终请求；停止后只发一次；动画/翻页节奏不受影响；窗口尺寸变化同理。

**边界**：不做交互中的低质量预览档（第一版只做尾随防抖 + 稳定帧）；不改动画调度；不增加新配置项。

**验收**：连续缩放/拖窗过程中画面不中途跳变；停止后一次稳定帧到位；动画与翻页首屏不卡；普通图片行为不变。

### 8. 右侧信息面板（CORE-30 收敛版）

**目标**：在主看图窗右侧加一个固定信息面板，专门显示当前图的信息；不做浮动 HUD、不做停靠/拆分/半透明浮层、不做 Notes/标签。

**施工点**：

- 布局：面板贴主窗右缘，占一列固定宽度（如 260–320 px，窄窗自动收起）；主图/辅图、缩略图条、文件树的可用区一起扣减；无边框形态隐藏。
- 开关：右键「信息面板」或工具栏按钮，默认关；开/关立即重排，不写窗口几何。
- 内容：第一版只做只读信息——文件名/路径、格式、尺寸、文件大小、页/帧数、缩放/DPI、EXIF 拍摄信息；后续再加直方图、Overview 等模块。
- 数据：复用现有 EXIF/属性窗的读取路径，按当前图/页更新；换图/翻页/换层时刷新；读取失败显示“无信息”，不阻塞看图。
- 边界：不做 Notes/标签/评分（管理边界）；不做插件面板 API；不做浮动/停靠/拆分；不做窗口几何记忆。

**验收**：开关面板时主图/辅图不越界、不遮挡；窄窗自动收起；换图/翻页信息跟着变；无 EXIF 的图显示空态；无边框下不出现；普通看图路径不因面板变慢。

### 9. BROWSE-01 全屏虚拟化照片墙

**目标**：大目录的网格选片视图；1 万项可用，跟随当前项；不做管理/评分/标签。

**施工点**：

- 复用现有缩略图管线/清单索引，不另建目录扫描；
- 网格按视口虚拟化：只创建可见格 + 少量缓冲，滚动回收复用；
- 当前项高亮，打开/翻页/切换目录时跟随；
- 全屏/常规两形态；与胶片条、文件树、右侧信息面板、主辅视图一起扣布局；
- 缩略图请求走现有队列，按可见范围发请求，滚动/换页取消过期请求；
- 不做多选/批量/评分/标签/拖拽管理。

**边界**：只作用于当前清单，不做全盘/递归索引；不做照片墙的编辑/管理；小目录不强制切换。

**验收**：1 万项目录滚动不卡；只解可见格；当前项跟随；与胶片条/树/信息面板不重叠；退出后主图状态不变。

### 10. BROWSE-05 跟随 Explorer 当前视图/筛选结果（插件优先）

**目标**：把 Explorer 当前窗口的视图/筛选/排序读成一份只读播放列表；不在核心主路径做双向同步。

**施工点**：

- 交付形态先插件：插件进程用 Shell COM（IShellWindows/SVGIO）取当前视图，把文件列表交给插件自己的窗口；宿主核心不直接依赖 COM。
- 若将来进宿主：只做“读一次当前视图”，不做实时双向同步；Explorer 视图变化时提供显式刷新，不后台轮询。
- 取不到/虚拟文件夹/搜索结果的项要跳过并提示；路径必须落到真实本地文件。
- COM 调用放独立线程，带超时/取消；失败回退到“当前文件所在目录”，不影响正常打开。
- 不做 Explorer 筛选的写回、不做跨进程选中跟随、不做网络/云路径。

**边界**：插件优先；宿主不把 Shell COM 变成核心依赖；不保证与 Explorer 的排序/筛选逐项一致。

**验收**：能按 Explorer 当前列表打开/翻页；取不到时回退原目录并提示；COM 挂起不拖死主窗；不做网络/虚拟项。

### 11. BROWSE-07 + BROWSE-18 左侧文件列表 + 底部过滤

**目标**：左栏列**当前目录 / 压缩包层**的文件（子目录、子包、图片），底部一条搜索框只筛这份列表。过滤依附于列表存在，不做独立的过滤窗口/浮层。

**施工点**：

- 普通目录：子文件夹 + 当前层图片；压缩包：当前层子包/子目录 + 图片；首行 `..` 或面包屑回上一层。
- 点文件夹/子包进层，点图片打开；宽度可收起、窄窗自动收、无边框不显示。
- 底部 `TextInput` 只筛当前列表：包含匹配、不区分大小写；↑↓ 选、Enter 打开、Esc 清空。
- 过滤只重建**可见行**（~20 行），查询防抖 ≥120 ms；不因一次击键重排整窗/重绘画布。
- 目录懒加载：只读当前层，进入子目录才读下一层；压缩包沿用现有层树数据，不另扫一遍。
- 目录变化用现有 watcher/rescan；不新建轮询。
- 不做全盘索引、不做重命名/删除/复制/移动、不做多选/拖拽移动。

**边界**：左栏是“看图的目录”，不是文件管理器；默认开还是按需开，实现时按宽度和单图场景定。

**验收**：普通目录/压缩包层都能列文件并打开；底部搜索即筛；进层/回层正确；大目录输入不卡；关掉左栏后主图状态不变。

### 12. BROWSE-24 缩略图分层调度

**目标**：缩略图按可见性/质量分车道：可见格先出预览，滚动停下再补高清；快速滚动时暂停后台补图；为以后提供缩略图/照片墙做调度基础。

**施工点**：

- 可见范围优先：视口内先发 Preview 档；离屏/缓冲格降级；停止滚动后再补 HQ。
- burst 停车：连续滚动/快速换页时暂停低优先级缩略图，只保当前视口；停下后恢复。
- 在途取消/去重：同一路径不重复发；过期视口请求作废；失败记忆保留。
- 与主图/预读共用解码队列时，缩略图不得压过主图首屏；车道优先级要显式。
- 现有缩略图缓存的 LRU/在途上限/失败记忆继续沿用，不另造缓存。
- 不做磁盘缓存（BROWSE-03 另议）、不做多 worker 线程池（先单队列分车道）。

**边界**：只调度现有缩略图请求；不新增缩略图 UI（网格/照片墙另条）；不做磁盘缓存/持久化。

**验收**：大目录快速滚动时主图不被缩略图拖慢；停下后可见格补高清；同一路径不重复解码；缩略图失败不刷屏；普通目录行为不变。

| 包内只有子目录的那一层是"空画面" | 画面空、给一句「这一层没有图片」；不当成打开失败（否则清单被清、左边的树也没了）。树里这种层用次要色画、图数不标 | 若真机上高频遇到，再考虑"自动下钻到第一个有图的子层" |
| 系统菜单跟着系统走，宿主不保证它长什么样 | 右键「系统菜单」是**转发** explorer 的文件菜单（m313）：装了 7-Zip 就有压缩、装了杀软就有扫描、改了默认看图器之后"打开方式"也在这里；没装就没有。宿主自己的菜单里**不会**出现这些动词（不复刻，否则内容就成了"我这台机器上长这样"）。原生菜单的明暗跟**系统**主题走，不跟本程序的「主题色」 | 若某类动词高频到需要固定入口（例如把「打开方式 ▸」单列），再在宿主菜单里加一项明确入口 |
| 单边 >16384 的位图 1:1 会略糊 | 显示侧按 GPU 纹理上限**等比降边**：30000×2000 → 16384×1092（横向损失约 45%），1080×20000 → 885×16384（两轴损失约 18%）；>64 MP 直接明确拒绝。位图没有 tile / 金字塔；矢量格式走区域渲染，不受此限 | 单边超限的分块 / 金字塔（CORE-18）属**质量档，不排期**；真有人拿长条 / 全景来问，先评估 2–4 块「分带上传」，不做完整金字塔；>64 MP 另需解码器按块解码（ABI v7），不在本条里承诺 |
| 辅图 >100% 放大比主图糊 | 主图纹理缓存声明了 `pixelated`，放大走最近邻；辅图 `comp_img` 用的是 `ImageCache::new()`，未声明，仍走双线性。同一张图在辅图放大到 100% 以上会比主图软。现有注释只写了“鸟瞰与缩略图条不置”，没提辅图 | 先确认辅图是否定位为“第二看图窗”：是，就给 `comp_img` 加 `pixelated`（一行）；若故意保持柔和，把理由写进注释，避免以后被当成 bug 反复改 |
| HDR 编码图按 SDR 显示 | JXL/AVIF/HEIF 的 PQ/HLG/EXR 等 HDR 内容解出后没有 tone mapping，直接当 SDR 上屏，可能过曝/偏色；当前是 8-bit RGBA 显示管线 | 等 HDR 语料/真实需求出现再评估；若做，先定解码器侧输出 SDR 还是显示侧 tone map，并准备 HDR 测试集；不在当前排期 |

全列在这儿，不藏。（行数会随边界增减，别写死数字。）
